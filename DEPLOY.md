# Постоянный сервер игры

Подготовлен один Docker-сервис: страница игры, модель камеры и WebSocket-сервер работают на одном адресе. Компьютер разработчика после публикации не нужен. Телефон и экран могут находиться в разных сетях.

## Render

1. Поместить проект в свой Git-репозиторий и подключить его в Render.
2. Создать Blueprint из `render.yaml` либо Web Service с Dockerfile из корня.
3. Пробный конфиг выбирает Free. Для работы без сна выбрать платный тариф отдельно; конфиг сам ничего не покупает.
4. После сборки открыть выданный HTTPS-адрес `*.onrender.com` на игровом экране, сканировать QR телефоном.
5. Проверить `/healthz`, затем `node scripts/check-relay.mjs https://АДРЕС` и распознавание на телефоне.

PUBLIC_ORIGIN не нужен: QR использует адрес открытой страницы. Можно задать его полным HTTPS URL без завершающего слеша при использовании собственного основного домена.

Free-сервис засыпает после 15 минут без входящего трафика; первое открытие после простоя требует ожидания. Есть лимиты часов, трафика и сборок. Условия: https://render.com/docs/free

## VPS / другой Docker-хостинг

Собрать: `docker build -t nu-pogodi .`

Запустить за HTTPS reverse proxy: `docker run -d --name nu-pogodi --restart unless-stopped -p 127.0.0.1:17891:10000 nu-pogodi`

Прокси направляет HTTPS-домен на порт 17891, сохраняет заголовки Host и Origin и поддерживает WebSocket Upgrade на `/ws`. Без HTTPS браузер телефона не предоставит камеру.

## Ограничения текущей версии

Работать должен один экземпляр сервера: комнаты хранятся в его памяти. После перезапуска/обновления сервера нужно обновить страницу игры и повторно подключить телефон по новому QR. Для нескольких экземпляров и сохранения комнат потребуется общее хранилище. Видеокадры остаются на телефоне.

Dockerfile подготовлен; факт успешного облачного развёртывания подтверждается отдельно после запуска на выбранном аккаунте.
